# 德州扑克筹码分配器（联机版）

一个基于 Node.js + WebSocket 的德州扑克筹码在线分配器，支持多人联机、实时下注、筹码买卖、场外带入、牌局历史记录等功能。适用于朋友聚会、线下牌局等场景。

## 功能特性

### 核心功能
- **多人联机**：支持最多 9 人同时在线，实时同步牌局状态
- **自动发牌/下注**：小盲/大盲自动扣除，翻前/翻后/转牌/河牌四轮下注
- **下注操作**：跟注、过牌、加注、全下、弃牌，支持滑块和快捷金额
- **撤销下注**：下错注码可撤销重下（下一个玩家下注前）
- **加时卡**：下注倒计时可使用加时卡延长时间
- **庄家操作**：房主可设庄家、换座、休息、移出玩家

### 筹码管理
- **筹码买卖**：玩家之间可互相购买筹码，需对方确认
- **场外带入**：玩家可继续代入筹码，需房主确认
- **筹码结算**：重置牌局时自动记录每位玩家的剩余筹码、买卖明细、带入明细
- **历史记录**：完整牌局动态永久保存，支持表格化查看，买卖/带入记录高亮显示

### 界面特性
- 响应式设计，适配手机和电脑浏览器
- 实时倒计时显示
- 底池、已下筹码、总筹码三栏实时显示
- 弃牌玩家在点选赢家时自动排除
- 休息玩家不再当庄

## 技术栈

- **后端**：Node.js + ws（WebSocket）
- **前端**：原生 HTML + CSS + JavaScript（单页应用，无框架依赖）
- **数据存储**：JSON 文件（state.json 状态 + history.jsonl 历史记录）
- **运行环境**：Node.js >= 16

## 快速开始

### 1. 安装依赖

```bash
npm install
```

### 2. 启动服务

```bash
# 方式一：直接启动
node server/server.js

# 方式二：使用启动脚本（Linux）
chmod +x start.sh
./start.sh

# 方式三：npm 启动
npm start
```

### 3. 访问应用

- HTTP 访问：`http://<服务器IP>:3017`
- 查看完整历史：`http://<服务器IP>:3017/history`

### 环境变量

| 变量 | 默认值 | 说明 |
|------|--------|------|
| `PORT` | `3017` | HTTP 服务端口 |
| `DATA_FILE` | `./data/state.json` | 状态文件存储路径 |

## 部署到 N1 盒子（Armbian）

本项目专为 N1 盒子等低功耗设备优化，可 7x24 小时运行：

```bash
# 1. 上传项目到 N1
scp -r poker-chip-settler root@<N1_IP>:/mnt/mmc1-4/poker-app

# 2. 登录 N1 并安装依赖
ssh root@<N1_IP>
cd /mnt/mmc1-4/poker-app
npm install

# 3. 启动
./start.sh

# 4. 设置开机自启（可选）
# 将 start.sh 添加到 /etc/rc.local 或使用 systemd
```

## 使用说明

### 房主操作
1. 第一个加入的玩家自动成为房主和庄家
2. 房主可在"玩家管理"中：换座、设为房主、休息、移出玩家
3. 房主可配置小盲/大盲、下注限时、加时卡数量
4. 每轮下注结束后，庄家点击"下一轮下注"或"结束本手"

### 玩家操作
1. 输入昵称和带入筹码加入牌局
2. 轮到自己时：跟注、过牌、加注、全下或弃牌
3. 可向其他玩家购买筹码，或请求场外带入
4. 下错注码可点击"撤销下注"重下（下一个玩家下注前）

### 牌局结算
1. 所有玩家弃牌或摊牌后，庄家点选赢家
2. 底池自动分配给赢家
3. 点击"重置牌局"结束当前牌局，系统自动记录每位玩家的筹码明细
4. 查看完整历史：访问 `/history` 页面，表格化展示所有动态

## 配置说明

在应用内"房主配置"中可设置：

| 配置项 | 说明 |
|--------|------|
| 小盲 | 小盲注金额 |
| 大盲 | 大盲注金额（通常是小盲的 2 倍） |
| 下注限时 | 每位玩家下注倒计时（秒） |
| 加时卡 | 每位玩家每手可用的加时卡数量 |
| 加时时长 | 每张加时卡延长的时间（秒） |

## 数据存储

- `data/state.json`：当前牌局状态（玩家信息、下注状态、配置等）
- `data/history.jsonl`：完整牌局历史记录（每行一条 JSON，永久保存）

**注意**：`data/` 目录包含玩家数据，不应上传到公开仓库。

## 安全说明

- `certs/` 目录存放 SSL 证书和私钥，不应上传到公开仓库
- 建议使用 HTTPS 代理（`https-proxy.js`）加密通信
- 生产环境建议修改默认端口并配置防火墙
